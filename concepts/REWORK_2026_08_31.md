## 1. Общая архитектура новой брони

Каждый сет — свой `EntityModel` (ModelPart, UV 128×128), корневые кости `head/body/
right_arm/left_arm/right_leg/left_leg` совпадают с игроком; слой `RenderLayer` делает
`copyFrom` родительской модели и рендерит с разбиением по надетым предметам
(visibility per piece). Эмиссив — второй проход `entityTranslucentEmissive` c FULL_BRIGHT.
Текстуры и Java-модели генерируются одним скриптом (единая таблица кубов → texOffs
гарантированно совпадают с UV-островами): `scripts/gen_armor_rework/<set>.py` пишет
PNG (+эмиссив, +16×16 иконки) и целый Java-файл модели.

Кости следуют иерархиям из промптов (armor_root → head/body/arms/legs), среди них
сохранены имена `head/body/right_arm/left_arm/right_leg/left_leg` для copyFrom.

## 3. Расширение ИИ (JapaneseWarriorEntity) — «додуманные» анимации в бою

Состояния: 0 none, 1 smoke_step, 2 long_lunge, **3 melee**, **4 throw** (клип есть,
ИИ без снаряда — QA), **5 guard**, **6 parry**, **7 dodge_l**, **8 dodge_r**, **9 command**.
- swing() → если none: MELEE на 10т (визуал = attack_horizontal/attack_fast).
- GUARD: цель ближе 5 блоков, шанс 1/40/т, кулдаун 100т, 24т стражки; урон в стражке −60%.
- PARRY: ближний бой попал в первые 8т стражки → урон отменён, отбив + звук, 10т.
- DODGE: при получении урона вне стражки шанс 30%, кулдаун 80т → перпендикулярный толчок
  + клип dodge_left/right.
- COMMAND: только самурай, при первой цели после ≥200т без цели — 16т «приказ».
- MeleeAttackGoal блокируется только на {1,2,5,6} (melee/dodge не прерывают бой).
- Контроллер: death (isDeadOrDying → death once), combat_idle при цели, hurt, техники.
- Vanilla-свинг-оверлей в RedShogunModel/DarkNinjaModel больше не нужен — убираем
  (оставляем hold-позу руки с предметом), кости right_arm/body/head сохраняются.

## 7. Хотфикс 2 (30.08.2026): сломанные модельки мобов
**Причина:** framework.alloc_uv упаковывал UV-острова по ДРОБНЫм размерам кубов
(размеры рига вроде 3.9×11.2 накапливали uv вида 27.6, 66.2). GeckoLib требует
целые box-UV (и сам файлит размеры кубов для UV) → семплирование мимо островов,
текстура «размазывалась» по модели.
**Исправление:** alloc_uv теперь пакует по ceil()-размерам и выдаёт ТОЛЬКО целые uv;
острова всегда покрывают файленные face-rect'ы GeckoLib. Перегенерированы оба рига
(red_shogun 65 кубов, dark_ninja 47 — дробных uv: 0).
Проверки: анимации↔кости OK, validate_resources OK, build SUCCESS.

## 8. Хотфикс 3 (30.08.2026): «голова внизу, тело прозрачное»
**Причина:** origin'ы кубов в japan.py были авторены ОТНОСИТЕЛЬНО пивота кости (привычка
Java ModelPart), а bedrock-гео требует АБСОЛЮТНЫЕ координаты (bbox старого рабочего рига:
y[0..37], нового: y[-15.25..11.3]). Ноги оказались под землёй (прозрачны/скрыты), голова —
на уровне земли. GeckoLib читает cube.origin как абсолют.
**Исправление:**
- framework.Model.absolutize_origins() — прибавляет пивот кости к origin (и к пивоту
  вращения) каждого куба; вызывается перед save в обоих генераторах.
- пивоты kusazuri (7.3→20.3) и hip_cloth (6.6→19.1) переведены в абсолют.
- Итог: shogun y[0..39.9] (до кончика полумесяца), ninja y[-0.05..31.3].
- Проверено фейтфул-рендером (точная UV-математика GeckoLib): оба персонажа целые,
  полный рост. Анимации↔кости OK, validate OK, build SUCCESS.

## 9. Хотфикс 4 (30.08.2026): летающие катаны и «сломанные» руки
**Катаны над головой:** WarriorHeldItemLayer переносил предмет на +armLength по Y,
а в системе координат кости GeckoLib +Y направлен К ГОЛОВЕ (пивот = плечо) → предмет
повисал над плечом. Рецепт ванильного ItemInHandLayer (XP −90, YP 180,
translate(±1/16, 0.125, −0.625)) в системе GeckoLib схлопывается в
`YP 180; translate(+1/16, −0.625, −0.125)` — кисть на −Y. Слой переписан.
**Руки:** аддитивная hold-поза (−0.5 rad на right_arm в setCustomAnimations) постоянно
выворачивала правую руку вперёд поверх клипов → удалена из обеих моделей; позы теперь
исключительно из анимаций (combat_idle = «рука на рукояти» и т.д.).
(В ходе работ 31.08 этот слой и оба rig-класса удалены полностью — см. §10.)
